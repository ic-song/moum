## 캘린더

한 회차 제목/시간/자원을 변경해 원래 기간 밖으로 옮긴 뒤 새 기간에 표시되는지 확인했습니다. 원래 회차 id/originalDate를 유지하고 원복·undo/redo하며 시리즈와 다른 회차를 보존합니다. 잘못된 반복 날짜·기간·필드·id 변경은 원자적으로 거절합니다. 종일 변경·자원 해제·제외 우선순위도 검사했습니다.

자원 필터 UI/일정 편집, 기간 조회 실패·재시도·중단·시간 초과·최신 응답 우선·destroy를 확인했습니다. 진행 중 조회 뒤 로컬 편집을 하면 신호를 중단하고 늦은 결과로 편집을 덮지 않습니다. 서버 조회 성공은 현재 이벤트와 편집 이력을 교체합니다. 예제는 지연·오류가 있는 로컬 로더이며 실제 서비스 서버 저장/권한은 검증하지 않았습니다.

## 페이지네이션

HTTP 예제에서 초기 URL의 페이지/크기를 읽고 요청·표시·URL이 일치하는지, 성공 후 history 항목이 늘어나는지 확인했습니다. 실제 브라우저 back/forward/reload와 페이지 직접 이동, 크기 변경·빈 결과·total 감소 보정을 검사했습니다. 다른 query/hash/history.state를 보존하고 URL 이동 조회 실패 시 마지막 성공 페이지와 URL을 유지하며 retry는 원래 실패 요청을 다시 실행합니다. destroy 뒤 popstate는 추가 조회하지 않습니다. URL 숫자/키 경계와 기존 stale/abort/timeout 검사를 유지합니다.

## 인피니티 스크롤

5,500개 데이터에서 화면 DOM은25개 미만이며 200,000px로 이동 후 목록/커서/위치를 스냅샷·다시 생성·sessionStorage/새로고침으로 복원했습니다. 가상 행의 aria-posinset/setsize와 화면 밖 포커스 행 유지도 검사했습니다. 렌더러 오류는 기존 목록을 유지하고 ‘표시 다시 시도’가 추가 조회 없이 복구합니다. 유효한 스냅샷 복원은 이전 요청을 중단하고 늦은 결과를 무시합니다. 중복 키·잘못된 버전/위치·개수 초과 스냅샷은 기존 목록을 보존합니다.

손상·만료·중복 키·저장소 용량 오류를 주입하여 상태 안내/콜백과 목록 보존을 확인했습니다. 느린 요청은 불러오기 취소 버튼으로 중단합니다. 캐시는 선택 사항이며 JSON 왕복이 가능한 데이터만 저장합니다. 데이터 최신성·사용자/검색조건 키 분리·로그아웃 시 삭제는 호스트 책임입니다. 가변 높이 가상화는 지원하지 않습니다.

## 화면 및 증거

초기 Calendar6개/Pagination3개, 최종 InfiniteScroll4개 연락 시트에서 모든 합성 이미지와 원본 조각을 검토하고 모바일 편집기·페이지 오류·가상 목록을 원본 크기로 재확인했습니다. 공통 폰트·44px 일반 컨트롤·포커스·줄바꿈을 유지합니다. Calendar 월간은7열을 읽을 수 있게 내부 가로 스크롤을 유지하며 문서 넘침과 구분합니다. 로딩·오류·빈 상태·회차 편집·자원 필터·페이지 이동·가상 목록을 캡처했습니다. 캐시 오류와 복원 완료 상태는 브라우저 기능 검사에서 확인했습니다.

로컬 증거: `.codex/design/reviews/navigation/reviewed-manifest.json`, `output/navigation-visual-gate.json`, `output/playwright/navigation`, `output/navigation-components-regression.log`. 개인 로컬 캡처는 Git에 포함하지 않으며 CI는 브라우저 결과를 artifact로 보관합니다. 시각 게이트의 반응형 미디어쿼리 경고는 flex-wrap/고정 행 높이 구조와 실제 폭 검사로 확인한 비차단 항목입니다.
